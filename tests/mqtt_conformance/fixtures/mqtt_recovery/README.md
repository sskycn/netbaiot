# Historical NBMQ recovery fixtures

These are fixed bytes emitted by actual `netbaiot-server` binaries built from the
listed repository commits with `cargo +1.88.0 build --locked -p netbaiot-server`.
Each checkout and Cargo target directory was isolated under `/private/tmp`.
The server used its own `configs/development.json` with loopback listeners and a
new temporary spool directory, then received SIGTERM and exited successfully.
The files below are copies of its resulting `mqtt-runtime.state`; they are not
generated by the current v6 encoder or by a test helper.

For each nonempty image, CONNECT as the development credential using a distinct
`legacy-session-vN` ClientId and CleanSession 0; SUBSCRIBE with QoS1 to
`v1/t/demo/p/sensor/d/device-1/down`; publish a retained QoS1 heartbeat on
`v1/t/demo/p/sensor/d/device-1/up` using Packet Identifier 2, then publish a
QoS2 heartbeat on that same topic using Packet Identifier 7. Confirm SUBACK,
PUBACK and PUBREC, omit PUBREL, send DISCONNECT, and SIGTERM the server. The
exact acknowledgements, binary hashes and sample hashes are in
`docs/audit-evidence/mqtt-legacy-fixture-generation.json`. The subscription is
deliberately on a different topic so an onward PUBLISH cannot be mistaken for
the PUBREC. The nonempty fixture test verifies the retained message, subscription
and AwaitPubrel state before and after writing v6.

The v5 sample contains a persistent MQTT 5 session, a No Local subscription, inbound
QoS2 Packet Identifier 7 awaiting PUBREL, and an abnormal-disconnect Will with
a far-future delay. The old v5 encoder did not have an explicit Will origin; its
recorded delayed-cancellation key supplies the origin when v6 reads the file.
To reproduce that state, CONNECT as the development credential with ClientId
`legacy-will-client`, Clean Start 0, Session Expiry `0xffffffff`, and a QoS1
retained Will on `v1/t/demo/p/sensor/d/device-1/up` with Will Delay
`0xffffffff` and payload `fixed-will`. SUBSCRIBE to that topic with options
`0x05` (QoS1, No Local), then send a valid QoS2 PUBLISH with Packet Identifier
7 and the `event(777)` payload from `tests/mqtt_conformance/run.py`. Confirm
PUBREC, close the socket without DISCONNECT or PUBREL, and SIGTERM the server.
The test in `broker.rs` checks those states after reading the fixed sample and
after committing and reading a new v6 image. The existing v5 raw-record unit
test separately covers an old immediate Will with no cancellation key.
