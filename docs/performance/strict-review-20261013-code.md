## Resource contract

The default stable per-connection reader ceiling remains 65,540 bytes. No global or tenant default byte limit changes. Stable capacity includes every retained allocation, including the complete backing allocation of shared decoded slices. Only an exclusive old permit can start a replacement; retained aliases make `Arc::get_mut` fail and follow ordinary admission instead. Each new allocation must fit its own maximum, and projected stable capacity must fit the configured ceiling before the full new capacity is reserved globally and to the tenant.

During an exclusive copy, actual old and new buffers coexist, and both are charged. The local synchronous peak is bounded by twice the stable ceiling; there is no await, spawned task or quota waiter during that transition. Dropping the old physical buffer precedes dropping its quota. Commit rejects excess retained capacity and returns the pending guard on failure, allowing the transport to destroy the new physical bytes before releasing their reservation. An aborted guard releases its new permit before taking the reader lock to close the transition. Global and tenant pressure may still reject a legal packet when their actual aggregate capacity is exhausted; this is intended bounded admission.

For exclusive prefixes of at most eight bytes, the final permit is reserved/merged first, the prefix is copied to a fixed stack array, the old physical allocation is freed, and only then is the new allocation created. Failed admission leaves the old prefix, capacity and counters unchanged. A unique split backing allocation can be reclaimed without allocating; if reclaim cannot succeed, the same checked replacement rules apply. `BytesMut::capacity()` is verified against the reserved request for the pinned dependency instead of silently assuming equality.

The isolated allocator experiment observes requested live heap equal to charged copy capacity for old prefixes 9, 64, 4096, 32,768 and 65,539: 65,549, 65,604, 69,636, 98,308 and 131,079 bytes. Stable live storage is 65,540 bytes and released storage is zero in every case. These figures measure allocator requests, excluding allocator size classes and OS RSS. Failed same-tenant admission and a spare global connection admission prove both aggregate accounts are full at the peak. Original IP/tenant/device keys can be reused and both accounts refilled after cleanup.

All accounting paths maintain `connection counts -> read state` lock order. No lock crosses await. Checked addition, subtraction, conversion and tenant fixed-plus-variable multiplication precede commit. The 16-thread simultaneous replacement test holds all admitted peaks and observes exactly two 64-byte replacements admitted into 128 remaining global bytes, with the other 14 rejected. Shared and distinct tenants are covered; after release all byte/count/index ownership returns. Separate tests cover global/tenant rollback, foreign permits, overflow, early commit, guard abort/retry, task abort during authentication, timeout, EOF, and slices outliving their connection. Loom was not run; the concurrency evidence consists of native-thread barriers and Tokio cancellation tests.

## MQTT review and unchanged contracts

Two independent agents reviewed the final Reader/Quota/MQTT diff, including fixes added during review. No remaining P0/P1 defect was identified. This is bounded test and code-review evidence, not a formal proof.

The lazy containers and boxed channel concerns did not reproduce additional correctness defects. Read-only access and the reviewed shadowed empty cleanup methods do not allocate their backing collection. Generic `DerefMut` does create an empty Box; this type has no unconditional guarantee for arbitrary mutable access. Current runtime mutation sites use `insert`, `push_back` and `entry` for actual protocol work, and `clear`, `get_mut`, `values_mut`, `remove`, `pop_front` and `retain` avoid allocation on absent backing storage. Future mutable APIs need the same review. Removing the last element releases the owned collection, and queue-full/closed paths retain or roll back their message and frame-budget owners. Empty subscriptions, protocol exchanges, Will or expiry provenance are not removed solely to reduce memory. Existing targeted tests and measured broker/channel/session allocation probes remain part of the verification evidence; no unrelated collection or lock rewrite was made.

The final protocol run passes 77/77 MQTT 3.1.1 release-gate observations with 125/125 normative catalog coverage, including mature Mosquitto differential/CLI clients and TLS. MQTT 5 raw and mature Mosquitto checks pass, along with seven additional protocol regressions and 117 broker unit tests. Twenty-eight broker experiments remain manual/ignored in the ordinary test command; the relevant allocation probes were run separately. Final end-to-end tests pass 27/27, including one successful authentication followed by 10,000 real MQTT publishes and exactly one provider call.

These suites exercise QoS1/QoS2 ACK transitions, takeover/generation fences, persistent sessions, expiry, Will/delayed Will, retained state, capacity rollback, and NBMQ v6 fixtures. MQTT recovery and state ASan fuzz completed 290,560 and 110,853 executions respectively without crashes, each with a 30-second configured limit (31 seconds reported by the engine). These targets cover broker/recovery state rather than Reader, and ran before the final Reader deadline edit. The NBMQ v6 wire format, EventAccepted boundary, authentication lock order and supported MQTT profile are unchanged. No runtime external broker, message store, offline command queue or new protocol feature was introduced.
