# 多 Codec 加固性能与可靠性证据

日期：2026-10-11。完整审核见 [中文报告](../../codec-hardening-audit.zh-CN.md)。
基线是开始工作时实际 main 的 `6e16b31d5e4767d10943c7c98204eb3d5f7120a7`。
本机性能测量的生产代码为 `fb37a3c`；报告/测试工具提交 `2ead168` 没有改变该实现。
CI 后额外将基线 `auth.rs` 过期检查改为逻辑等价表达式以通过 Rust 1.88 Clippy；
性能二进制不包含该语法修正，测量提交与最终交付提交明确区分。

## 方法与环境

本机为 macOS 27.0.1 ARM64、10 个逻辑 CPU，Rust 1.99.0、LLVM 23.1.1。
两个 release 网关二进制预先冻结，在同一机器串行执行，相同 Python 负载工具、相同
资源配置，没有同时编译或运行其它测试。实际监听回环 MQTT/TCP/UDP 和管理 HTTP，
必需 Webhook Sink 由独立有界 HTTP 接收器返回 204 ACK。没有使用内存 Sink 替代。
网关 10 个 Tokio worker、Sink 并发 4；每个客户端每次只有一个未完成上报，负载器
等待确认 Webhook 响应后再发下一条。HTTP 接收器最多 8 个 handler，pending 上限 64。

主矩阵：4 Codec ×（MQTT 3.1.1/5.0 各 QoS0/1/2、TCP、UDP）×3 种上报，
以及 4 Codec ×（MQTT 两个版本 QoS1、TCP）命令，共 108 场景，每场景 3 次。
每次 4 个客户端、0.3 秒发送窗口，速率分母包含连接建立和有界结果轮询。小遥测
2 个数字字段；大遥测流式路径为 64×128 B 文本，UDP 为 4×128 B，仍受 1200 B
原始 envelope 限制；Heartbeat 包含递增序号。命令有数字和 128 B 文本参数，设备
接收后检查与独立规范编码器一致的完整字节。TCP 每帧刻意拆分前三字节。

延迟定义：发送前 payload 已编码；socket send → PUBACK/PUBCOMP/TCP 接纳回执/
验签通过的 NBA1；另测 socket send → Webhook 接收器 flush 204 响应。后者不是
网关观察 ACK 的时间，更不是业务最终完成。QoS0 没有协议接纳回执，速率依据确认
Webhook 响应。命令是管理 HTTP 提交 → 设备收到字节，不表示设备执行。

CPU 来自 ps 的进程 CPU 时间（10ms 分辨率，100% 表示占满一个逻辑核）；RSS 每
100ms 采样。表中的峰值只表示采样峰值。每连接增长是该场景采样最大 RSS 减启动
场景时 RSS、再除客户端数，受进程保留容量影响，不能等同独立连接的堆大小。
所有场景的 CPU、空闲/稳态/采样峰值 RSS、近似增长、队列清理和 P50/P95/P99
均在 [summary.json](summary.json)，环境/显式配置在 [environment.json](environment.json)。
汇总取每次结果的中位数；不混合不同运行的百分位，不宣称统计显著性。

## 资源、故障和恢复

75 组统计分配矩阵（每个二进制 Codec 25 组）：1/2/16/64/65 字段，文本长度
0/16/128/256/257 B；默认 decoded_bytes=65,536 B、字段上限 64、字段文本上限
256 B、嵌套上限 8。每 Codec 15 组成功，最大累计分配 CBOR 21,421 B、MessagePack
21,091 B、Protobuf 16,964 B；10 组拒绝的最大累计分配分别 24,477/24,142/0 B。
额外超大长度声明在拥有型解码前零分配拒绝。不是所有无效输入都零分配，也不将
输入 byte bound 或此矩阵解释为任意限额下的完整运行内存保证。

独立慢 Sink 回归实际接纳 16 条必需投递并填满有界责任，下一条返回 Overloaded，
且拒绝不增加计数/字节；开放 Sink 后全部 ACK 并验证各层清零。既有测试覆盖慢 Sink
隔离、超时/短暂服务不可用、认证缓存、UDP 重放/错误签名/窗口、QoS2 takeover、
会话 incarnation 与失效 fence、恢复损坏和 spool 写失败。完整测试输出有 SHA-256。

32 客户端的慢 Sink 成对网络补测：每个小遥测场景 0.2 秒、1 轮，Webhook 延迟
10ms，四 Codec 的全部八路径各实际运行。旧/新确认 2,972/2,980 条事件，均无
客户端错误或拒绝，各场景结束队列和连接清零。场景速率变化中位数 +0.52%，
采样峰值 RSS 最大值 11,056→11,072 KiB。发送器主动等待 Sink 后再发，故该测试
说明有界并发/慢消费的完整链路行为，不是最大发送压下的零拒绝承诺；强制拒绝由
前述容量填满回归独立覆盖。32 并发仍不是百万连接或生产峰值测试。

多 Codec 实际重连/control soak 60.02 秒，241 轮、3,856 条接纳事件，含四 Codec、
MQTT3.1.1/5.0 QoS1/2、TCP 分片和 HMAC UDP，结束无在线会话；独立子进程
restart soak 64.80 秒，强制 spool/recovery 后进行健康 drain。没有小时/天级 soak。
NBSP v3、NBMQ v6 和 stable event_id 未变；允许 replay duplicates，未声称 exactly-once
或意外断电持久性。60 秒回归不能证明长期 RSS 无增长。

三个 ASan binary fuzz 各 31 秒，总 7,210,108 次，另扩展 corpus 后各 10,000 次，
原 JSON/MQTT/MQTT5/TCP/UDP/restart spool 各 10,000 次，全通过。macOS atos
符号化警告没有 sanitizer 错误；ASan quarantine RSS 与正常进程 RSS 不混比。
