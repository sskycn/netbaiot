the words `runtime ready` before the server was ready. The harness now waits for
authenticated `/api/v1/ready` and the complete smoke passed. One initial tooling
test also exposed macOS `/var` versus `/private/var` aliasing; link validation now
resolves the repository root before comparing it. No runtime changes or skipped
correctness checks were used to resolve either test issue.

The first Actions run then caught a sanitizer test failure on Linux: a dynamic
`/tmp` root matched inside the historical macOS `/private/tmp` path. macOS's alias
resolution hid that overlap locally. Root replacement now requires a path start,
and a regression simulates Linux root resolution on every platform. The corrected
9-test release tooling suite passed locally before the follow-up push.

## Publication hygiene

381 text artifacts under `docs/performance/` were sanitized, including V3 command
readiness gateway/loadgen configs, summaries, HOL evidence, dependency listings,
and historical validation logs. Two standalone reports were also sanitized:
`docs/business-rpc-v3-hol2.zh-CN.md` and `docs/mqtt-protocol-fix-report.md`.
Only machine-local paths changed; numeric measurements, revisions and historical
version references remain. Public PEM integration fixtures were retained.

`scripts/scrub_paths.py` derives repo, temporary and home roots dynamically and
handles historical checkouts from other usernames. The V3 readiness/HOL harnesses
scrub completed output after child shutdown, including failed runs. Live configs
are not scrubbed while processes need them. Other harness output must pass the
same sanitizer before publication; release preflight checks the evidence tree.

GitHub private vulnerability reporting was initially disabled. The owner enabled
it during preparation; the public GitHub API then confirmed `enabled: true`.
The [Security Policy](../../SECURITY.md) links the private report form.
