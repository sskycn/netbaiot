## Upgrade and compatibility

Business RPC V4 is the only accepted business wire version. Upgrade business
clients together with the gateway: V3 and earlier clients, and unknown versions,
are rejected during bootstrap. V4 formalizes the existing `Scalar::Decimal`
contract without changing frame layout, authentication, flow control, application
ACK or command semantics. Device JSON v1, MQTT 3.1.1/5.0, management `/api/v1`,
MQTT recovery NBMQ v6 and EventBus recovery NBSP v3 remain supported.

Rust source names are now independent of the wire version. Use
`netbaiot_protocol::business_rpc::wire::Rpc*`, `BusinessRpcClient`,
`BusinessRpcClientConfig`, `BusinessRpcDelivery` and `netbaiot-rpc-mux`.
Update old version-specific imports; no compatibility aliases are provided.
Configuration uses `business_rpc.limits`, `send_ahead` and
`experiment_socket_send_buffer_bytes`. Update monitoring to
`netbaiot_business_rpc_mux_*`, socket tracing to
`NETBAIOT_BUSINESS_RPC_SOCKET_TRACE`, and loadgen inputs to `rpc`/`rpc_dual`
topologies with `rpc_*` measurements. See the [wire reference](../business-rpc.md).

When upgrading from `v0.3.3` or earlier, also complete the
[integer Decimal configuration migration](../migration/integer-decimal.md)
introduced in `v0.3.4`. Business consumers must handle `Scalar::Decimal`.

Review the changes above and the [protocol support](../protocol-support.md),
[upgrade requirements](../migration/current-protocol-only.md) and
[operations guide](../operations-guide.md) before deploying.
Quiesce the previous process and wait for successful graceful shutdown; preserve
supported recovery files containing unacknowledged required work. Consumers must
deduplicate replay using stable `event_id`. Planned restart recovery does not
provide crash durability.

See [platform support](../platform-support.md) for release assets and
[benchmarks](../benchmarks.md) for measurement scope and limitations.
