# NetbaIoT v0.2.4

[English](v0.2.4.md)

## 亮点

NetbaIoT 现在优先支持 Linux 生产部署，发布时必须同时提供原生 x86_64 与 ARM64 包。
本版本还包含 v0.2.3 之后合并的有界 EventBus 记账、租户 backlog quota 与业务 sink
outage 处理。项目仍是无需运行时数据库、以内存为主的单节点 IoT 网关，内嵌 MQTT
3.1.1/5.0，并支持分帧 TCP 与认证 UDP。

## 平台与发布资产

- Linux x86_64 与 ARM64 是正式生产 target。两个压缩包都必须通过原生质量/恢复测试、
  release build、解压后 binary 启动、MQTT/TCP/UDP 端到端 smoke 和精确集合 SHA256
  验证，才可发布。
- required asset 为 `netbaiot-v0.2.4-x86_64-unknown-linux-gnu.tar.gz`、
  `netbaiot-v0.2.4-aarch64-unknown-linux-gnu.tar.gz` 与 `SHA256SUMS`。GNU binary 在
  Ubuntu 24.04 构建；部署到其他发行版前检查 loader/glibc 兼容性。
- macOS x86_64 与 Apple Silicon 继续作为开发/测试平台，支持源码构建、原生开发检查与
  独立可选 artifact。
- Windows x86_64 MSVC 为实验性平台。保留源码构建及既有恢复/网络兼容性，但不承诺
  生产稳定性或每个版本都有 binary。独立手动检查会正常报告失败。
- macOS/Windows 失败不阻断 Linux 发布；历史 Release 资产不变。共享 target policy 与
  严格路径、link、格式、架构和 checksum 校验会拒绝不完整或标签错误的包。

构建与部署细节见[平台支持](../platform-support.zh-CN.md)。

## 可靠性与资源安全

- required sink responsibility 使用增量维护的记账。重复/stale completion 不能二次释放
  所有权；重试、pause 和 spool recovery 会一直持有已接纳责任，直到 ACK。
- 已接纳 Event backlog 除全局和独立 sink 限制外，还按 tenant 的数量与序列化字节限制。
  admission/restore 仍原子执行，失败会 rollback。
- required sink 在 permanent/repeated failure 后暂停，通过有界 probe 恢复。HTTP failure
  有明确分类；429/503 的有界 `Retry-After` delta-seconds 遵守配置 retry ceiling。
  socket write 或失败 callback 永不算业务 ACK。
- sink 诊断包含 pending age、pause state 和封闭 failure-reason 词表；identifier 与 sink URL
  不进入 metric label。
- 真实 TLS MQTT QoS1/webhook outage 和计划重启回归覆盖稳定 event ID、已确认投递、
  资源清理与恢复所有权。

## 性能

EventBus usage read 不再扫描全部已接纳 backlog；webhook 序列化借用现有 event，不额外
构造 JSON tree。[工程报告](../engineering-optimization.md)记录本地 allocation、latency、
outage 与 restart 测量、tradeoff 和被测 commit。这些是 subsystem/local 测量，不是
生产容量或 SLA 声明。

## 兼容性

- Workspace crate 从 0.2.3 升到 0.2.4。`DeviceEvent`、MQTT、TCP/UDP、Business RPC
  V3、`EventAccepted`、业务 ACK、在线命令与 TLS/管理边界保持既有 wire 和责任语义。
- Sink delivery metadata 与管理诊断为 additive change。既有 `EventSink::deliver` 实现
  通过默认 detailed-delivery adapter 继续工作。
- 配置新增 `limits.event_queue_max_count_per_tenant`（默认 16384）与
  `limits.event_queue_max_bytes_per_tenant`（默认 67108864）。旧配置仍可解析；提高过
  全局预算的部署需要复查新租户限制。见[配置](../configuration.zh-CN.md)。
- 恢复格式仍为 EventBus NBSP v3 与 MQTT NBMQ v6。旧版或未知格式明确失败；没有旧版
  parser fallback 或 runtime migration。不得把限制降到已提交恢复责任所需容量以下。

## 升级说明

1. 下载与主机架构匹配的压缩包，并使用 `SHA256SUMS` 验证。在 Linux 上可运行
   `sha256sum -c SHA256SUMS --ignore-missing`，同时保留发布时的压缩包文件名。
2. 替换 binary 前复查 tenant backlog、required sink failure 行为与 GNU binary 的发行版要求。
3. quiesce 旧进程并等待优雅关机成功。保留配置与受支持恢复文件；不得删除未确认责任来
   绕过恢复或容量错误。
4. 替换 `netbaiot-server` 与 `netbaiot`，重启后验证 readiness 和 required sink ACK。
   业务 consumer 必须按稳定 `event_id` 幂等处理重放。

若从仍含旧 Business RPC 或旧恢复格式的版本升级，先执行
[当前协议升级步骤](../migration/current-protocol-only.zh-CN.md)。

## 已知限制

- 单节点；没有集群 session、横向 HA 或跨节点命令路由。
- 不支持 MQTT-SN、WebSocket、共享订阅、Topic Alias、Subscription Identifier、
  Enhanced Authentication、bridge mode 或 `$SYS` 服务。
- UDP 已认证但未加密，没有 session 或命令下行。
- 计划重启恢复不是 crash durability；突然的进程、机器或电源故障可能丢失有界近期
  内存事件与 MQTT 状态。
- 离线命令、历史遥测与业务持久化仍由外部系统负责。项目尚未 1.0，不提供生产容量或
  长期 API 兼容性承诺。
