# NetbaIoT v0.2.3

## Highlights

This patch prepares a verified, directly runnable binary release and includes
correctness fixes merged after v0.2.2. NetbaIoT remains a database-free, memory-first,
single-node IoT gateway with embedded MQTT 3.1.1/5.0, framed TCP, and authenticated UDP.

The implementation changes below are traceable to
[`e53a4f3`](https://github.com/sskycn/netbaiot/commit/e53a4f36f595e60e76d7c4c99c06d7b336af27d8)
and [`6d16bf8`](https://github.com/sskycn/netbaiot/commit/6d16bf82207383a37c118bfc862708f375821cc3).
The complete [v0.2.2 → v0.2.3 comparison](https://github.com/sskycn/netbaiot/compare/v0.2.2...v0.2.3)
also includes the test and documentation commits.

## Reliability

- Lifecycle admission fences management control/routes changes, Business RPC
  auth sync/invalidation, provider revocation, and command dispatch during quiesce.
- Auth invalidation completes before a planned MQTT recovery snapshot can commit;
  stale authenticated candidates cannot register after admission closes.
- Final MQTT/TCP session registration and MQTT attachment hold admission through
  bounded handshake side effects. Diagnostic reads and idempotent drain remain available.
- Command queue validation and failed reservations release their count/byte ownership.

## Commands

- Process-local command dedup returns the latest known transport delivery state,
  including queued expiry, instead of retaining only the initial `Queued` result.
- Unsent MQTT QoS0 commands have explicit bounded ownership across broker handoff,
  dequeue, expiry, disconnect, session reset, and write failure. Terminal cleanup
  releases the responsibility and reports failure once.
- `Sent`, device receipt, and execution remain distinct. There is no automatic
  business retry, durable command history, or offline command queue.

## Security

- HTTP auth providers can use a Bearer service identity supplied through
  `NETBAIOT_AUTH_PROVIDER_TOKEN` for both authentication and verifier resolution.
  It is optional for compatibility; remote providers are not automatically authenticated.
  Production operators should configure it. Token validation and sensitive header
  handling prevent it from appearing in request Debug output.
- A [Security Policy](../../SECURITY.md) documents supported releases and private
  vulnerability reporting. Public test keys remain test-only fixtures.
- Published performance evidence removes machine-local repository, temporary, and
  home paths. The affected report harnesses sanitize completed output before publication.

## MQTT

- MQTT 3.1.1 and the bounded MQTT 5.0 profile retain QoS0/1/2, persistent sessions,
  retained messages, Will, and exact/`+`/`#` subscriptions.
- Additional raw regression tests cover unsent command ownership and accounting.
- Reference broker timing observations are classified separately; a NetbaIoT
  normative failure still fails the release gate. Mosquitto remains a test dependency only.

## Performance

UDP replay bookkeeping indexes expiry and per-device/per-tenant counts, avoiding
repeated full-map scans while retaining the existing authentication and duplicate
receipt rules. No production throughput improvement or percentage speedup is claimed.
The [hardening report](../lifecycle-command-hardening.md) records local microbenchmarks
and their limitations. EventBus retry queue and MQTT recovery ownership formats
were preserved.

## Documentation and release process

- Updated English/Chinese project positioning, Quick Start, design philosophy,
  protocol matrix, delivery semantics, comparison, and benchmark caveats
  ([`97d8188`](https://github.com/sskycn/netbaiot/commit/97d8188)).
- Binary archives include the tutorial config, demo webhook and MQTT/TCP/UDP
  examples, public guides, Security Policy, and contributing instructions.
  Linux/macOS can run `./scripts/demo/start.sh` without Rust in a binary archive;
  Windows has manual PowerShell commands in the [Quick Start](../quick-start.md).
- A tag must exactly match workspace and lockfile versions and have a nonempty
  `docs/releases/<tag>.md`. Rust 1.88.0/stable checks, audit, protocol regressions,
  MQTT release gate, MQTT 5, and SDK interoperability precede all release builds.
- The original candidate pipeline required five platforms. The current
  [Linux-first policy](../platform-support.md) requires Linux x86_64 and ARM64,
  actual native archive smoke on both, and exact-set SHA256SUMS. macOS/Windows
  builds are independent and optional; historical assets are unchanged.

## Compatibility

Crate version changes from 0.2.2 to 0.2.3. This patch does not introduce a new
device or Business RPC wire version, change the configuration schema, or change
the recovery writer format. EventBus writes v2 and reads v1/v2; MQTT writes NBMQ
v6 and retains read-only compatibility with v1–v5. API callers that relied on a
duplicate command always reporting `Queued` should handle its latest known state.

## Known limitations

- Single node; no horizontal HA cluster, shared sessions, or cross-node command routing.
- No MQTT over WebSocket, shared subscriptions, MQTT-SN, bridge mode, or `$SYS` services.
  Topic Alias, Subscription Identifier, and Enhanced Authentication are also outside
  the bounded MQTT 5.0 profile.
- UDP is authenticated but unencrypted and has no session or command downlink.
- Successful planned restart recovery is not crash durability. Abrupt process,
  machine, or power failure can lose bounded recent in-memory traffic and MQTT state.
- At-least-once business delivery can duplicate `event_id`; consumers must be idempotent.
- Pre-1.0; this release is not a production capacity certification or a long-term
  API compatibility guarantee. Business persistence and offline retries remain external.

## Upgrade notes

1. Verify the downloaded archive with the published `SHA256SUMS` (for example,
   `sha256sum -c SHA256SUMS --ignore-missing` on Linux). Keep the matching archive
   name when checking. The binary names remain `netbaiot-server` and `netbaiot`
   (`.exe` on Windows).
2. Quiesce and wait for the old process to complete graceful shutdown; retain the
   existing spool directory and configuration for the replacement process.
3. Replace the binaries, restart with your existing configuration, and verify
   readiness and required sink acknowledgements. Expect idempotent replay.
4. Configure `NETBAIOT_AUTH_PROVIDER_TOKEN` if using an HTTP authority that accepts
   Bearer service authentication. Do not reuse tutorial credentials in production.
5. Review the [delivery semantics](../delivery-semantics.md),
   [operations guide](../operations-guide.md), and
   [contributing guide](../../CONTRIBUTING.md).
